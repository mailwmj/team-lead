# Models and dispatch mechanics

Cross-project observations; the date is when first seen, on the version current then. Names below are model families: use the newest id `list_models` shows for the family unless the project pins one. agy carries its thinking level in the model id suffix (`-high`, `-xhigh`). The project's DISPATCH routing table decides who gets what; this file informs that table and the card wording. When appending to an entry, compress it to current conclusions plus data-point counts rather than keeping a chronological log; move a line out when it stops being true.

## Paseo dispatch

- Highest thinking level means `xhigh` (agy: the `-xhigh` id); `max` and `ultra` delegate subtasks and lose control of scope, so use them only when the project says so.
- Check the model exists with `list_models <provider>` right before `create_agent`; ids get retired (2026-11-20). Right after a provider outage `list_models` can return a partial list (agy showed only Hydrogen while Neon/Carbon were fine): re-query once a few minutes later, or ask the user, before falling back (2026-11-27). It lists this host only; on a remote host, a failed `create_agent` is the signal.
- Label every agent `team-lead=<project>` at creation so a later lead can find them.
- pi: pass only `settings.thinkingOptionId`, no `modeId`. agy: `settings.modeId: "full-access"` (its only mode), passed explicitly even when the lead runs in bypassPermissions (2026-11-25). Codex: `full-access` unless the project says otherwise.
- Switching model mid-card: `archive_agent` the old session and confirm with `list_agents` it is gone before the new one starts in that worktree (one writer); the new session first reviews the uncommitted work, then continues.
- Stalled pi run: send "continue from where you stopped", up to 3 times; 429 `account_concurrency_exceeded` is transient. 401 `auth_unavailable` ("IP is not authorized") is not: switch line at once (2026-11-23).
- Remote host agents: answer their questions and permission requests with `send_agent_prompt` (`respond_to_permission` does not reach them); you cannot `update_agent` a remote agent's model, start a new one instead (2026-11-07, 11-20).
- A `create_agent` to a remote host that times out may still have been created: `list_agents` by title before resending (2026-11-11).
- Finish notifications go to the session that created the agent. After a coordinator handoff, message every running agent so it reports to the new lead (2026-11-08).
- A message to a running agent queues until its turn ends. Coordination it needs now (a file to avoid, an upstream fix) goes with `activeTurnBehavior: "steer"`; an unread steer is lost if that turn stops or is interrupted (2026-11-25).
- `get_agent_status` needs the full agent id; short ids fail (2026-11-25).
- Activity only updates when a command finishes; a long silence during a build or suite is not a hang (2026-11-07). Wait for notifications; when one is lost or a run goes well past what its card warrants (check once, or set a bounded `create_heartbeat` and `delete_heartbeat` when done), inspect `get_agent_activity`: if the session is churning across failed attempts (context rot) or stuck on an unbounded command rather than a clean drop, `archive_agent` (confirming with `list_agents` it is gone), salvage or reset the worktree, and split or tighten the card for a fresh session instead of sending `continue`.
- Agents ask the user directly in the app for physical steps; send your message only when they are not mid-question (2026-11-08). A remote agent stuck on a question: prefer the user tapping in the app; to answer it yourself, interrupt it, wait for status error, then send the answer (2026-11-20).
- Keep one lead session per project at a time (2026-11-08).
- Codex `auto` mode makes `.git` read-only: fetch before dispatching a review in that mode (2026-11-08).
